# KeyBuddy 환경 리소스 생산 워크플로 (Draft v0.1)

## 1. 문서 목적

이 문서는 마을과 던전에 배치할 환경 리소스를 `Low Companion v1`의 캐릭터 비주얼과 같은 화면 안에서 일관되게 제작하기 위한 최초 규칙이다.

현재 단계의 목표는 완전 자동화가 아니라 다음 네 가지다.

1. AI로 만든 마스터 이미지를 최종 픽셀 아트로 오인하지 않는다.
2. 원하는 논리 해상도와 화면상 크기를 먼저 고정한다.
3. 반복 가능한 가공 순서를 만들고 마지막 픽셀 판단은 사람이 보정한다.
4. 정적 오브젝트와 소규모 루프 애니메이션을 동일한 규격으로 Unity에 투입한다.

이 규칙은 최초 환경 리소스 5~10종을 실제 게임 화면에서 검증한 뒤 갱신한다.

---

## 2. 핵심 결론

환경 리소스는 아래 순서로 제작한다.

> 환경 Brief → AI 마스터 이미지 → 목표 논리 크기 결정 → 저해상도 블록아웃 변환 → 수동 픽셀 보정 → 필요 시 소규모 애니메이션 → 정수 배율 확대 → Unity 검증

AI 마스터 이미지는 형태·구도·색감 참고용이다. 마스터에 단순 픽셀화 필터를 한 번 적용한 결과를 최종 리소스로 사용하지 않는다.

픽셀 밀도의 기준은 원본 이미지 해상도가 아니라, 먼저 정한 `논리 픽셀 크기`와 `논리 픽셀 1칸을 최종 이미지에서 몇 배로 표시하는가`로 관리한다.

현재 프로젝트의 기본 가설은 다음과 같다.

- 편집용 논리 픽셀: 1×1
- 최종 출력 배율: 3배
- 화면에 보이는 기본 픽셀 블록: 3×3 물리 픽셀
- Unity PPU: 기존 캐릭터와 동일하게 200 유지
- 확대 방식: Nearest Neighbor 전용

이 값은 최초 환경 리소스의 실제 빌드 비교 후 조정한다.

## 3. 기존 캐릭터 규칙에서 계승할 내용

다음 규칙은 기존 캐릭터 생산 규칙을 그대로 계승한다.

### 3.1 비주얼 언어

- 최상위 스타일 기준은 `Low Companion v1`이다.
- 기준 이미지는 `Assets/Art/ReferenceSheets/low-companion-v1-barbarian-reference.png`를 사용한다.
- 외곽선은 검정에 가까운 짙은 색을 사용하고 계단형 픽셀 군집을 유지한다.
- 색은 장식용으로 무한히 늘리지 않고 형태와 재질을 설명하는 색만 사용한다.
- 기본 광원은 좌상단에서 들어오는 것으로 통일한다.
- 안티앨리어싱, 반투명 테두리, JPEG 노이즈, 흐릿한 외곽선은 제거한다.
- 배경은 투명 RGBA가 원칙이다.
- 오브젝트 자체에 외부 투영 그림자를 굽지 않는다. 필요한 접지 그림자는 별도 리소스로 분리한다.

### 3.2 프레임 규칙

- 애니메이션의 모든 프레임은 같은 캔버스 크기와 같은 피벗을 사용한다.
- 프레임 사이에서 오브젝트 전체가 흔들리거나 미끄러지지 않아야 한다.
- 프레임은 합본 시트보다 개별 투명 PNG를 우선 사용한다.
- 파일 번호는 2자리 연속 번호를 사용한다.
- Unity에서는 Point Filter, No Compression, Alpha Is Transparency를 사용한다.
- 실제 게임 크기에서 캐릭터와 함께 비교한 뒤 승인한다.

### 3.3 작업 게이트

- Brief 승인 전에 최종 리소스 생산을 시작하지 않는다.
- 마스터 승인과 픽셀 결과 승인을 분리한다.
- 확대된 미리보기만 보지 않고 실제 게임 배율에서도 확인한다.
- 자동 변환 결과는 중간 산출물이며 최종 승인 대상은 수동 보정된 결과다.

## 4. 캐릭터 규칙에서 그대로 계승하지 않을 내용

다음은 캐릭터 전용 규칙이므로 환경 리소스에 고정 적용하지 않는다.

- 모든 결과를 512×512 캔버스로 만드는 규칙
- 캐릭터 가시 높이 약 70 논리 픽셀 규칙
- 발바닥 중앙을 기준으로 한 단일 피벗 규칙
- 항상 전신이 보이고 화면 오른쪽을 바라보는 구도
- Idle, Attack, Hit, Recovery 등 캐릭터 전용 모션 분류

환경 오브젝트는 용도에 맞는 타이트한 캔버스와 피벗을 사용한다. 단, 같은 애니메이션 묶음 안에서는 캔버스와 피벗을 통일한다.

---

## 5. 환경 오브젝트 크기 규칙

환경 오브젝트는 캐릭터와의 상대 크기를 먼저 정하고, 그다음 논리 픽셀 크기를 정한다.

현재 캐릭터의 가시 높이 약 70 논리 픽셀을 비교 자로 사용한다.

| 구분 | 예시 | 최초 권장 논리 크기 |
|---|---|---:|
| 미세 장식 | 풀 한 포기, 작은 돌, 꽃 | 8~24 px |
| 소형 소품 | 표지판, 랜턴, 상자, 항아리 | 20~40 px |
| 중형 소품 | 테이블, 의자 묶음, 작은 제단 | 35~80 px |
| 대형 구조물 | 건물, 큰 나무, 동굴 구조 | 한 장보다 모듈 분할 우선 |

위 수치는 MVP 기준 가설이다. 폭과 높이 중 형태를 설명하는 축을 기준으로 사용하며, 실제 배치 시 캐릭터와 비교해 조정한다.

### 5.1 캔버스

- 정적 오브젝트는 실루엣 바깥에 논리 픽셀 1~2칸 정도의 안전 여백만 둔다.
- 애니메이션은 전체 프레임 중 가장 큰 실루엣을 기준으로 공통 캔버스를 만든다.
- AI 마스터의 여백을 그대로 유지하지 않는다.
- 최종 물리 이미지 크기는 기본적으로 `논리 크기 × 3`으로 만든다.

### 5.2 피벗

| 오브젝트 유형 | 기본 피벗 |
|---|---|
| 바닥에 서는 소품·건물 | Bottom Center, 접지점 기준 |
| 벽 장식·오버레이 | 배치 기준점 또는 Bottom Center |
| 매달린 간판 | 구조물은 Bottom Center, 흔들리는 간판은 경첩 위치 |
| 반복 타일 | 타일 원점 또는 Center |
| 물·바닥 스트립 | 타일 연결 기준점 |

| 목표 논리 크기 | Width × Height |

| 금지 요소 | 텍스트, 배경, 그림자, 추가 오브젝트 등 |

## 7. AI 마스터 이미지 생성 규칙

### 7.1 AI에 맡길 범위

AI는 다음을 탐색하는 데 사용한다.

- 실루엣
- 재질 구분
- 색 조합
- 장식 구조
- 테마 변형안

AI가 직접 확정하지 않는 항목은 다음과 같다.

- 최종 픽셀 밀도
- 정확한 외곽선 군집
- 팔레트 최종 색 수
- 접지점과 피벗
- 루프 애니메이션의 프레임 연결

### 7.2 프롬프트 기본 요구

- 하나의 오브젝트만 생성한다.
- 투명 배경을 요청한다.
- 텍스트, UI, 바닥면, 외부 투영 그림자를 제외한다.
- 승인된 캐릭터 또는 기준 이미지를 스타일 참고로 함께 전달한다.
- 환경 오브젝트만 출력하고 캐릭터는 결과에 포함하지 않도록 명시한다.
- 카메라 시점, 좌상단 광원, 외곽선 강도, 안전 여백을 명시한다.
- “완성 픽셀 아트”보다 “Low Companion v1용 환경 마스터”라고 역할을 제한한다.

### 7.3 마스터 승인 기준

- 작은 크기에서도 실루엣으로 종류가 구분된다.
- 캐릭터보다 디테일 경쟁이 심하지 않다.
- 움직일 부분과 고정할 부분을 분리할 수 있다.
- 얇은 선에만 의존하지 않는다.
- 목표 논리 크기로 줄였을 때 핵심 특징이 남을 가능성이 있다.

## 8. 마스터에서 픽셀 리소스로 가공하는 표준 루트

### Step 1. 목표 논리 크기 확정

마스터를 줄이기 전에 캐릭터 대비 화면 크기와 목표 논리 Width/Height를 먼저 정한다.

### Step 2. 투명 배경 정리

투명 PNG를 우선 사용한다. 배경 제거가 필요하면 색 번짐과 반투명 halo를 정리한다.

### Step 3. 논리 해상도 블록아웃 생성

- 마스터를 목표 논리 크기로 한 번만 축소한다.
- 최초 축소는 영역 평균 계열을 사용해 큰 색 덩어리를 얻는다.
- 디더링은 기본적으로 끈다.
- 이 결과는 실루엣과 색 배치를 잡는 블록아웃일 뿐 최종본이 아니다.

단순히 고해상도 이미지에 모자이크 필터를 적용하거나 임의 배율로 반복 축소하면 오브젝트마다 픽셀 밀도가 달라지므로 금지한다.

### Step 4. 팔레트 축소

- 소형 오브젝트는 불투명 색 6~12색부터 시작한다.
- 중형 오브젝트는 10~20색부터 시작한다.
- 테마 공용 팔레트가 생기면 공용 팔레트를 우선한다.
- 색 수보다 같은 역할의 유사색이 불필요하게 늘어나는지를 먼저 본다.

위 색 수 역시 최초 가설이며 재질 표현에 따라 조정할 수 있다.

### Step 5. 수동 픽셀 보정

다음 순서로 보정한다.

1. 실루엣과 접지면
2. 외곽선 계단과 두께
3. 가장 큰 명암 덩어리
4. 재질을 설명하는 핵심 특징
5. 좌상단 광원 통일
6. 단독으로 튀는 1픽셀 노이즈 제거
7. 투명 가장자리와 halo 제거

마스터 축소 과정에서 사라진 밧줄, 풀 끝, 간판 연결부 등은 논리 해상도에서 다시 그린다.

### Step 6. 정수 배율 출력

- 논리 결과를 Nearest Neighbor로 정확히 3배 확대한다.
- 2.5배, 3.2배처럼 비정수 확대를 사용하지 않는다.
- 확대 이후에는 선형 필터나 리샘플링을 다시 적용하지 않는다.

### Step 7. 게임 화면 검증

- 캐릭터 옆에 배치한다.
- 에디터 확대 화면과 실제 게임 화면을 모두 본다.
- Stage 50%, 100%, 150%에서 형태와 픽셀 밀도를 확인한다.
- 환경이 캐릭터보다 더 선명하거나 더 조밀해 보이면 논리 디테일을 줄인다.

## 9. 소규모 환경 애니메이션 규칙

환경 애니메이션은 화면을 점유하지 않으면서 정지 화면의 생명감을 보완하는 용도로만 사용한다.

### 9.1 기본 원칙

- 가능한 경우 고정 구조와 움직이는 부분을 분리한다.
- 전체 오브젝트를 매 프레임 다시 그리지 않는다.
- 루트와 접지부는 고정한다.
- 애니메이션 강도는 캐릭터 기본 공격보다 약해야 한다.
- 같은 오브젝트를 여러 개 배치할 때는 추후 시작 프레임 또는 시작 시간을 분산한다.

### 9.2 최초 권장 규격

| 종류 | 권장 프레임 | 권장 FPS | 방식 |
|---|---:|---:|---|
| 풀 흔들림 | 3~4 | 4~6 | 뿌리 고정, 끝부분만 1~2 논리 픽셀 이동 |
| 물 흐름 | 4~8 | 4~8 | Seam 유지, 하이라이트 군집 이동 |
| 매달린 간판 | 4~6 | 3~6 | 구조물 고정, 경첩 피벗 기준 Ping-Pong |
| 랜턴·빛 반짝임 | 3~4 | 3~6 | 위치 고정, 밝기·형태를 최소 변화 |

### 9.3 프레임 검수

- 첫 프레임과 마지막 프레임 연결이 튀지 않는다.
- 캔버스와 피벗이 동일하다.
- 애니메이션 때문에 외곽 전체가 흔들리지 않는다.
- 실제 게임 크기에서 움직임이 보이되 시선을 계속 빼앗지 않는다.

## 10. 도구 사용 권장안

### 10.1 즉시 사용

1. **OpenAI Image API 또는 ChatGPT 이미지 생성**: 마스터 후보와 부분 수정
2. **Aseprite**: 현재 설치된 도구를 사용해 논리 해상도 보정, 팔레트 정리, 프레임 애니메이션 제작
3. **Unity**: 실제 배율과 정렬 검증

이 경로는 새 유료 에셋 구매나 새 도구 개발 없이 바로 실행할 수 있다.

### 10.2 무료 대안

- **Pixelorama**: 무료 오픈소스 픽셀 편집·애니메이션·타일 작업 도구
- **LibreSprite**: 무료 오픈소스 픽셀 편집과 프레임 애니메이션 도구
- **Krita**: 마스터 정리, 팔레트·인덱스 컬러 실험, 이미지 시퀀스 작업
- **ImageMagick**: 반복되는 크롭·정수 배율 확대·파일명 정리용 배치 도구

ImageMagick 같은 자동 도구는 블록아웃과 반복 처리에만 사용하고 최종 픽셀 품질 판단은 Aseprite 또는 Pixelorama에서 한다.

## 12. Unity 투입 규칙

- Texture Type: Sprite (2D and UI)
- Sprite Mode: Single
- Filter Mode: Point
- Compression: None
- Alpha Is Transparency: On
- Generate Mip Maps: Off
- Pixels Per Unit: 200
- 애니메이션 프레임의 Mesh Type: Full Rect 권장
- Transform Scale: 기본 1, 비정수 스케일 금지
- 애니메이션 프레임은 동일 피벗 사용

### 12.1 현재 계층구조 배치 기준

| 용도 | 배치 위치 |
|---|---|
| 두 모드 공통 플레이어·전투 FX·배치 기준 | `CommonFieldRoot` |
| 마을 후방 환경 | `TownFieldRoot/EnvironmentBack` |
| 마을 건축물 | `TownFieldRoot/BuildingRoot` |
| 마을 NPC | `TownFieldRoot/NpcRoot` |
| 마을 전경 환경 | `TownFieldRoot/EnvironmentFront` |
| 던전 후방 환경 | `DungeonFieldRoot/EnvironmentBack` |
| 던전 몬스터 | `DungeonFieldRoot/MonsterRoot` 또는 현재 전투 슬롯 구조 |
| 던전 전경 환경 | `DungeonFieldRoot/EnvironmentFront` |

EnvironmentBack은 캐릭터와 몬스터 뒤, EnvironmentFront는 캐릭터와 몬스터 앞에 그려지는 자원만 배치한다. 최종 앞뒤 순서는 Hierarchy보다 SpriteRenderer의 Sorting Layer와 Order in Layer를 명시적으로 관리하는 방향을 사용한다.

## 13. 최초 검증용 리소스 제안

첫 환경 리소스는 복잡한 건물보다 아래 네 가지로 검증한다.

1. 마을 풀 한 포기: 3~4프레임 루프
2. 마을 작은 간판 또는 랜턴: 고정 구조 + 움직이는 부분
3. 던전 돌무더기: 정적 리소스
4. 던전 얕은 물 또는 발광 결정: 4~6프레임 루프

이 네 종류로 다음을 확인한다.

- 캐릭터와 환경의 픽셀 밀도 일치 여부
- Town과 Dungeon의 계층 및 정렬 규칙
- 정적·루프 리소스의 공통 제작 규격
- AI 마스터에서 수동 보정까지 실제 소요 시간
- 3배 출력 규칙의 타당성

## 14. 전용 툴 개발 판단

현재는 환경 생성 전용 툴을 새로 만들지 않는다.

환경 리소스 5~10종을 만든 뒤 아래 작업이 반복된다는 사실이 확인되면 작은 보조 도구만 추가한다.

- 투명 영역 자동 크롭
- 목표 논리 캔버스에 맞춘 1회 축소
- 공용 팔레트 적용 또는 색 수 경고
- Nearest Neighbor 정수 배율 출력
- 프레임 파일명 정리
- 실제 게임 크기 미리보기와 Contact Sheet 생성

권장 형태는 완전한 생성기가 아니라 다음 설정을 읽는 `Environment Normalizer`다.

```json
{
  "resourceId": "town_grass_a",
  "logicalWidth": 18,
  "logicalHeight": 14,
  "exportScale": 3,
  "pivot": "bottom_center",
  "paletteKey": "town_default",
  "alphaThreshold": 0.5,
  "padding": 1
}
```

이 도구는 미술 판단을 대신하지 않고 반복되는 크기·파일·출력 작업만 줄여야 한다. 최초부터 PerfectPixel에 대규모 환경 생성 기능을 추가하면 아직 확정되지 않은 규칙까지 코드로 굳어질 가능성이 크므로 보류한다.

- 다음 리소스에서 변경할 규칙
